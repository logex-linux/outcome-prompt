# 示例：从原始需求到可执行提示词

这些是改写样例，数字、数据字段和验证方式应随实际任务调整。

## 只回复一条差评：保持范围

原需求：只给我一段回复这条差评的提示词，别加分析。

```text
根据下方差评和店铺已确认的处理政策，起草一条公开回复。让顾客知道我们理解了哪项具体问题，以及下一步如何联系或处理。语气诚恳，不争辩。未核实的责任和未获批准的退款、换货不作承诺；政策不足时只给可以确认的后续步骤。只输出回复正文。

差评：【待填：差评原文】
店铺政策与已确认情况：【待填：处理政策和已核实信息】
```

## 找到重复差评的原因：证据与验证

原需求：我有过去 90 天的差评和退货记录。写个提示词找出反复出现的问题，并给我下一步措施。

```text
分析附件中最近 90 天的脱敏差评与退货记录，找出最值得优先处理的重复问题，并提出可试行的预防措施。

先说明两份记录的覆盖范围与缺失字段。若可用脱敏订单 ID 关联，以订单为单位去重；无法可靠关联时分别统计，说明可能重叠。按顾客描述归类，按商品或批次对照高频问题；每项主要判断附记录编号、计数口径和反例或局限。频数与发生率分开，只有分母可用时才计算发生率。

交付一张优先级表：问题、证据、已确认事实、待验证原因、建议动作。为首选动作定义试行范围、改前基线和改后检查口径。现有记录不足以确认原因时，列出下一批要核对的原始记录。只提出建议，不更改商品页面或联系客户。
```

## 做季度复盘 PPT：让受众能决策

原需求：把这些数据做成一份给管理层看的季度复盘 PPT。会议只有 30 分钟。

```text
根据附件中的季度数据和现有汇报模板，制作一份中文季度复盘 PPT。让管理层在 30 分钟内看懂哪些指标变了、哪些解释有证据，以及下一季度需要拍板什么。

先核对指标口径和前后期是否可比。选出最影响决策的变化，标注数据出处，把观察到的变化、可能原因和还缺的证据分开。用对照图展示关键差异；每项待决策议题给可选方案、取舍、推荐项与成立条件。关键结论应能用附件复算。

保留指定模板与交付格式。把讨论时间计入 30 分钟。若附件不足以支持某项因果解释，保留为待验证假设，不用推测补齐。
```

## 探索更快的页面：把挑战和承诺分开

原需求：帮我写提示词找出怎么把报告页加载时间从 10 秒降到 5 秒，最好挑战一下 200 毫秒。

```text
诊断报告页的加载瓶颈，给出一项可验证的优化方案。先在同一数据量、设备、网络和缓存条件下测量基线，说明“加载完成”的测量事件；用性能追踪区分服务端等待、资源加载和渲染耗时。按实测瓶颈选取最小改动，在相同条件下重复测量并核对结果正确性。

验收目标是 5 秒以内；200 毫秒是探索目标。若后者需要改变缓存、预计算或页面交互，单列假设、收益与代价。没有运行环境时，交付可执行的测量计划，标明哪些结果还未实测。交付诊断和验证方案，不部署。
```
